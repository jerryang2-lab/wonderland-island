# 📋 Code Review 標準模板

---

## 🎯 目的
- 確保提交的程式碼符合團隊 **品質、可讀性與安全性** 標準。
- 減少 bug 與技術債，提升維護性與可測試性。

---

## ✅ 檢查清單
| 類別 | 檢查項目 | 說明 | ✅/❌ |
|------|----------|------|------|
| **程式碼風格** | 是否遵循團隊的 lint / formatter 規範？ | 例如 ESLint、Prettier、Black 等。 | |
| | 命名是否具備可讀性與一致性？ | 變數、函式、檔案命名遵循慣例。 | |
| **功能正確性** | 邏輯是否符合需求說明？ | 包含邊界條件與錯誤處理。 | |
| | 是否有遺漏的情況或未處理的例外？ | | |
| **效能** | 是否有明顯的效能瓶頸？ | 如不必要的迴圈、重複的 I/O、同步阻塞等。 | |
| | 有無適當的快取或懶載入策略？ | | |
| **安全性** | 是否避免了常見的安全漏洞？ | 如 XSS、SQLi、CSRF、Command Injection 等。 | |
| | 敏感資訊是否已加密或遮蔽？ | | |
| **測試** | 是否新增或更新了單元 / 整合測試？ | 測試覆蓋率 ≥ 80%（視專案而定）。 | |
| | 測試是否通過 CI？ | | |
| **文件與說明** | 是否更新了相關的 README、API 文件或註解？ | 包含函式說明、參數型別、返回值。 | |
| **相依性** | 是否新增或升級了套件？ | 確認相依性在 `package.json` / `requirements.txt` 中正確宣告。 | |
| | 有無潛在的版本衝突？ | | |
| **回溯與版本控制** | 是否使用了適當的 commit message 格式？ | 例如 Conventional Commits。 | |
| | 是否只包含單一目的的變更？ | | |
| **CI/CD** | CI 是否全部通過？ | 包含 lint、測試、建置、部署流程。 | |
| | 部署腳本或環境變數是否有變更？ | | |

---

## 📝 附加說明
- **程式碼片段**：如有需要，可在此提供關鍵程式碼的 diff 或說明。
- **影響範圍**：說明此變更影響的模組、服務或使用者。
- **風險評估**：列出可能的風險與對應的 mitigation 計畫。
